    点击顶部「下载」按钮走一遍流程。默认是 Android App 内置浏览器、未装 Chrome，引导弹窗已打开。

    改什么

    用户点「下载 App」时，如果当前浏览器装不了 PWA（多数是 Facebook、TikTok 等 App 内置浏览器），现在点了没反应。改成：

    • Android：先尝试直接用 Chrome 打开当前页；拉不起来（没装 Chrome 或被拦截）时，弹出「复制链接，用 Chrome 打开」引导窗。
    • iOS 非 Safari：弹同款引导窗，文案和图标换成 Safari（iOS 上只有 Safari 能添加到主屏幕）。
    • 能正常安装 PWA 的浏览器（Android Chrome 等）和 iOS Safari：保持现有流程，不弹这个窗。

    流程

    点击「下载 App」→已收到 beforeinstallprompt？
    是→调起原生安装（现有）
    否 · iOS Safari→现有「添加到主屏幕」引导
    否 · iOS 其他浏览器→弹窗：复制链接用 Safari 打开
    否 · Android→intent 拉起 Chrome，等 1.5s→页面切走 = 已打开 Chrome/页面仍可见 = 弹窗：复制链接用 Chrome 打开

    规则

    项规则
    判断「不能安装」页面加载后监听 beforeinstallprompt，点击时没收到这个事件就算不能安装。已经以 PWA 方式打开（display-mode: standalone）时不显示下载入口，沿用现有逻辑。
    拉起 Chrome（Android）intent://77slot.com/?inv=…#Intent;scheme=https;package=com.android.chrome;end，路径和参数用当前完整 URL。拉起后 1.5 秒内触发 visibilitychange（页面变成隐藏），就算成功，不弹窗；否则弹窗。网页无法检测手机是否装了 Chrome，只能这样试。
    链接当前页面完整 URL，必须带上邀请码、渠道号等参数，否则注册归因会丢。展示框单行，超出显示省略号。
    复制链接优先 navigator.clipboard.writeText，失败时用隐藏输入框 + execCommand('copy') 兜底（部分内置浏览器禁用剪贴板 API）。成功后 toast 提示「已复制」，弹窗保持打开，方便用户再复制。两种都失败时，toast 提示「复制失败，请长按链接复制」，展示框里的文字允许长按选中。
    取消 / 遮罩点「取消」关闭弹窗；点遮罩不关（防误触）。每次点「下载」都重新走一遍判断。
    样式按原型：白底圆角卡片，左「取消」白底，右主按钮用站点主色（橙）。宽度跟随屏幕，左右留 18px。
    语言只做英文，文案见下表。

    验收

    编号环境 / 操作期望
    A1Android · Facebook 内置浏览器，已装 Chrome，点下载直接跳到 Chrome 打开同一链接（参数完整），不弹窗
