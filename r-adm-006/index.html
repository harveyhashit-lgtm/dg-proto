关闭榜单赛

确认关闭「每日投注排行」？

新增
    关闭后不可撤销：当期不会补结算，作废的奖励不会恢复；重新开启从新的一期开始。

    数据为演示数据。打开页面默认弹出期次奖励明细；切到「榜单赛列表」默认弹出编辑弹窗（演示每日投注排行）。

    改什么

    • 榜单赛记录 › 期次奖励明细：加「导出」；「待领取」的真实玩家奖励可「强制通过」「强制拒绝」，支持勾选批量。
    • 榜单赛列表 › 编辑：「结算发奖时间」「奖励领取方式」「领取过期时间」「未领取奖励处理」四项支持配置。
    • 关闭榜单赛：状态改为「关闭」并保存时，当期不再结算，所有待领取奖励作废。
    现状：明细弹窗只能看、只有「关闭」；发错的奖励只能找开发清库。编辑页四项是灰的：结算时间、过期天数后端已存但界面锁着，领取方式写死「用户手动领取」，未领取处理写死（固定奖池作废、其它奖池滚入下一期）。

    强制处理流程

    明细里的奖励行真实玩家 + 待领取 才可操作→单条点按钮，或勾选后批量→确认弹窗拒绝须填原因，批量共用一个→后端逐行再查状态
    强制通过→已领取：入红利钱包，按「榜单赛奖励打码倍数」加打码
    强制拒绝→已取消：会员端不显示、不能领取，金额不滚入下一期
    某行状态已变→跳过该行，提示「N 行状态已变化，已跳过」

    期次奖励明细

    位置规则
    导出新增弹窗底部「关闭」左边。导出本期全部奖励行（含机器人），列：期号、榜单赛类型、名次、机器人、UID、得分、奖金、状态、奖励单号、处理时间、处理人、拒绝原因。复用后台现有导出，写导出日志。文件名 榜单赛明细_<期号>_YYYYMMDD_HHmm.csv
    勾选与批量新增只有真实玩家、「待领取」的行可勾选；表头勾选 = 全选这些行。勾选后显示「已选 N 人 / 合计 ₱X」，「批量强制通过」「批量强制拒绝」可点
    操作列新增可操作的行显示「强制通过」「强制拒绝」；机器人行和已领取 / 已过期 / 已取消的行显示「—」
    状态「已取消」新增强制拒绝后的状态。会员端榜单赛奖励不显示、不能领取
    汇总「已取消人数 / 金额」新增放在「已领取人数 / 金额」后面；强制通过计入已领取，强制拒绝从待领取移到已取消

    字段规则默认

    打码倍数不变，只读，读数据字典「榜单赛奖励打码倍数」—

    关闭榜单赛修改

    现状：状态改「关闭」只停止新参与和计分，当期照常结算发奖，待领取仍可领。关闭时结束这个榜单赛的后续事项：

    项关闭后
    参与与计分停止，前台不再展示进行中
    当期进行中或「待结算」的那一期不再结算，奖池不发放；比赛状态显示「已关闭（不结算）」
    待领取奖励这个榜单赛所有期次里待领取的奖励全部作废，状态「已取消」，会员端不再显示，金额不滚入下一期
    已领取不受影响
    重新开启从新的一期开始计分；已作废的不恢复
    触发系统反馈
    编辑弹窗把状态从「开启」改为「关闭」，点保存配置先弹「关闭榜单赛」确认：列出停止计分、当期不再结算、待领取几人共多少金额作废、已领取不受影响；写明不可撤销；按钮「确认关闭」为红色
    确认关闭保存成功，列表状态「关闭」；提示「已关闭，当期不结算，作废 N 人待领取」；写操作日志（含作废人数、金额）
    状态本来就是「关闭」，改其它配置保存直接保存，不弹关闭确认

    接口

    接口说明
    POST …/jackpot/rewards/force-approvebody { rewardNos: [] }，单条与批量共用；返回成功与跳过明细
    POST …/jackpot/rewards/force-rejectbody { rewardNos: [], reason }
    期次明细奖励行加 status=cancelled、处理时间、处理人、原因；汇总加 cancelledCount / cancelledAmount
    赛制保存加 claimMode（manual / auto）、unclaimedAction（void / auto_credit）；settleTime、claimExpireDays 放开可写，生效从下一期
    前台榜单赛奖励不返回已取消的奖励
    赛制保存（状态改关闭）服务端同时取消当期结算、作废所有待领取，返回作废人数和金额；新增关闭前预览接口，返回确认弹窗要显示的数量

    不做

    撤销强制操作或关闭；已领取奖励扣回；打码倍数配置位置调整；参赛门槛、奖池上限等保护项。

    验收

    编号前置条件与操作期望结果
    A1打开一期已结算的明细底部有「导出」；真实玩家待领取行有勾选框和「强制通过」「强制拒绝」；机器人行没有
    A2点导出下载本期全部行（含机器人），列齐全；导出日志有记录
    A3单条强制通过该行「已领取」；会员到账并按字典倍数加打码；汇总待领取减、已领取加
    A4单条强制拒绝不填原因提示「请填写拒绝原因」
    A5勾选 3 行批量强制拒绝并填原因3 行「已取消」；汇总出现已取消 3 人 / 合计金额；会员端看不到；金额不滚入下一期
    A6批量处理时其中 1 行会员刚领取其余行成功，提示 1 行状态已变化已跳过
    A7编辑每日投注排行：结算时间改 02:00、领取方式改系统自动派发，保存保存成功；过期时间、未领取处理置灰；列表结算时间显示 02:00；下一期 02:00 结算并直接到账，当前期不变
    A8手动领取、过期 3 天、过期自动派发到账下一期结算后 3 天未领的奖励自动到账
    A9领取过期时间填 0 或 31 保存提示「领取过期时间须为 1 到 30 的整数天」
    A10赛制开启状态下改四项可以保存；资金与范围类字段仍冻结
    A11查后台操作日志强制操作、配置修改都有记录
    A12开启中的每日榜单，状态改「关闭」点保存先弹「关闭榜单赛」确认，列出当期不结算、待领取人数和金额
    A13确认关闭当期不结算（比赛状态「已关闭（不结算）」），所有期次待领取变「已取消」，会员端看不到；已领取不变
    A14关闭时恰好在结算发奖时间以先完成的为准：已结算出来的待领取也一并作废，不出现关闭后还能领
    A15关闭后重新开启从新的一期开始；已作废的不恢复

    开发测试重点

    • 关闭要拦住结算任务：结算发奖任务执行前检查赛制状态，已关闭的不结算；关闭与结算并发时，结算出的待领取也要作废。
    • 只认待领取的真实玩家：机器人奖励只展示、不发奖，接口要拒绝机器人行。
    • 批量逐行校验：每行以提交时的状态为准，已变的跳过，不整批失败、不重复入账。
    • 已取消不外显、不结转：会员端榜单赛奖励、可领汇总都要排除；取消的金额不进下一期奖池。
    • 发奖设置从下一期生效：已经结算出来的待领取奖励，过期时间和过期处理按结算时的配置，不因改配置而变。
    • 自动派发与过期自动派发：到账效果和会员自己领取一致，按字典打码倍数加打码。
