    开启活动

    列表数据为演示数据。「活动列表 · 关闭活动」里关闭某个活动后，切回「活动订单」能看到该活动的待领取订单变成「已取消」。时间按站点时区。

    改什么

    运营配置 › 活动订单页加两项：

    • 导出：按当前筛选条件把发奖记录导出为 CSV。
    • 待领取奖励人工处理：「待领取」的订单可以「强制通过」（直接到账）或「强制拒绝」（作废，会员端不显示），支持单条和勾选批量。
    • 关闭活动：活动列表点「关闭」时，同时结束该活动后续的派送，并作废还没领的奖励。
    现状：「操作」列只有「派发失败」的订单有「重试」，其它显示「—」；没有导出。异常奖励目前只能找开发手工处理。

    强制处理流程

    订单状态「待领取」其它状态不显示这两个按钮→单条点按钮，或勾选后批量→确认弹窗拒绝须填原因→后端逐笔再查状态
    强制通过→已到账：入红利钱包，按订单流水快照加打码
    强制拒绝→已取消：会员端不显示、不能领取
    状态已变（会员刚领取 / 刚过期）→单条提示「订单状态已变化，请刷新」；批量跳过该笔

    按钮与规则

    位置规则
    导出新增「发奖记录」卡片右上角、「刷新」左边。导出当前筛选条件下的全部记录（不只当前页），列与列表一致（不含「操作」）。复用后台现有导出：单次上限 10,000 行，超出提示缩小时间范围或只导出前 10,000 行；导出中可取消；写导出日志（操作人、时间、筛选条件、行数）。文件名 活动订单_YYYYMMDD_HHmm.csv
    操作 · 强制通过新增只对「待领取」显示。确认后状态「已到账」、写到账时间，奖励进会员红利钱包，按订单上的流水倍数、流水基数快照加打码（赠送金额：奖励 × 倍数；本金+赠送：（本金快照 + 奖励）× 倍数）
    操作 · 强制拒绝新增只对「待领取」显示。必须填原因（1–200 字）。确认后状态「已取消」，会员端 Bonus / 活动记录不显示，不能领取，不加打码
    勾选与批量新增列表第一列加勾选框，只有「待领取」可勾选；表头勾选 = 全选当前页的待领取订单。勾选后上方显示「已选 N 笔 / 合计 X」，「批量强制通过」「批量强制拒绝」可点。只处理当前页勾选的订单，一次最多 100 笔；翻页、改筛选、刷新后清空勾选。批量通过的确认弹窗显示笔数、涉及会员数、合计奖励、合计打码要求（各笔按自己的流水快照算）；批量拒绝共用一个原因
    操作 · 其它状态「派发失败」仍是「重试」；已到账、已过期、已取消、派发中显示「—」
    触发系统反馈
    点「导出」右上角出现导出进度「导出… 已获取 x / N 行」；完成后下载文件并提示「已导出 N 行」
    导出时筛选结果超过 10,000 行提示上限，可选「导出前 10,000 行」或取消
    强制通过 · 确认提示「已强制通过」，该行变「已到账」，到账时间为当前时间；写操作日志
    强制拒绝 · 没填原因点确认原因框下提示「请填写拒绝原因」，不提交
    强制拒绝 · 填原因确认提示「已强制拒绝」，该行变「已取消」；写操作日志（含原因）
    提交时订单已不是「待领取」单条：提示「订单状态已变化，请刷新」，不入账、不改状态
    批量提交完成提示「成功 N 笔，跳过 M 笔（状态已变化）」；成功的行更新状态，勾选清空

    活动列表 · 关闭活动修改

    现状：点「关闭」只是不再产生新订单，已产生的待领取仍可领取，已开始的结算周期照常派送。关闭时结束这个活动所有后续事项：

    项关闭后
    新的参与和触发停止，不再产生新订单
    还没派送的部分不再派送：每日返水当日已累计未结算的部分、亏损救援还在观察中的窗口、连续存款进行中的后续档位、免费转盘未用完的次数等，都不再结算或发放
    待领取 / 派发失败的订单全部作废，状态「已取消」，会员端不再显示、不能领取；派发失败的不再重试
    派发中的订单照常完成
    已到账的奖励不受影响，打码要求不变
    重新开启只对之后新的参与生效；已作废的不恢复
    触发系统反馈
    点某个开启中活动的「关闭」弹出「关闭活动」确认：第一行「确认关闭「活动名」？」，下面逐条列出影响：停止新参与；进行中的周期 / 窗口 / 进度数量（该类型有时）；待领取和派发失败共几笔、多少金额将作废。底部写明不可撤销、已到账不受影响；按钮「确认关闭」为红色
    确认关闭状态变「关闭」，提示「已关闭，作废 N 笔待领取」（没有待领取时提示「已关闭」）；写操作日志（含作废笔数、金额）
    点关闭中活动的「开启」沿用现有确认「确认开启「活动名」？」，开启后只对新的参与生效

    接口

    接口说明
    POST …/activity-orders/force-approvebody { orderNos: [] }（1–100 笔），单条与批量共用；只处理待领取，返回成功 / 跳过明细
    POST …/activity-orders/force-rejectbody { orderNos: [], reason }；同上
    导出复用现有导出：按活动订单列表接口分页拉取，完成后写导出审计
    前台活动订单 / Bonus 列表「已取消」的订单不返回
    活动开关 PATCH …/activities/{id}/state关闭时服务端同时作废该活动的待领取、派发失败订单，取消未结算的周期 / 窗口 / 进度；返回作废笔数和金额。新增关闭前预览接口，返回确认弹窗要显示的影响数量

    不做

    跨页批量；撤销强制操作或关闭；已到账订单扣回。

    开发测试重点

    • 关闭要覆盖所有后续：各活动类型的定时结算任务（返水、亏损救援、连续存款等）在执行前都要检查活动是否关闭；关闭和会员领取并发时，以先完成的为准，不能已作废又到账。
    • 批量逐笔校验：每笔以提交时的状态为准，已变的跳过，不整批失败、不重复入账；打码按每笔自己的快照算。
    • 只认待领取：前端按钮和后端接口都要校验状态，后端以提交时的状态为准，防止和会员领取、过期任务并发造成重复入账。
    • 打码用订单快照：强制通过按订单上的流水倍数 / 基数 / 本金快照计算，不读活动当前配置。
    • 已取消不外显：会员端所有奖励列表、可领金额汇总都要排除已取消。
    • 导出范围：是筛选条件下的全部数据，不是当前页；时间按站点时区。
